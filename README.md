## 1. Тестийн зорилго

`POST /registrations` функцийг бие даан тестлэх. `PUT /students/:id` болон `PUT /courses/:id` хүсэлтээр өгөгдөл бэлтгэж, HTTP статус болон JSON result утгыг шалгасан. Collection-ийн `baseUrl` хувьсагч нь `http://localhost:3000`.

| Сонголт | Эквивалент анги | Төлөөлөх утга |
|---|---|---|
| studentID | Байгаа, идэвхтэй | active |
| studentID | Байгаа, идэвхгүй | inactive |
| studentID | Байхгүй | Бүртгээгүй ID |
| studentID | Талбар дутуу | studentID оруулаагүй |
| coursesTaken | Суурь хичээл хангана | ["CS201"] |
| coursesTaken | Суурь хичээл хангахгүй | [] |
| courseID | Байгаа | Бэлтгэсэн ID |
| courseID | Байхгүй | Бүртгээгүй ID |
| prerequisites | Бүгд судалсан | ["CS201"], судалсан |
| prerequisites | Судлаагүй | ["CS201"], судлаагүй |

Төлөөлөх утгууд нь дизайны жишээ; collection-д тест бүр өөрийн LAB05_TC дугаартай ID ашиглана.

## 3. Тестийн спецификаци

| ID | Нөхцөл / setup | HTTP | Result |
|---|---|---:|---|
| TC01 | Идэвхтэй оюутан, суурь хичээл хангасан курс | 201 | OK |
| TC02 | Оюутан байхгүй, курс байгаа | 200 | ERROR_NO_STUDENT |
| TC03 | Идэвхгүй оюутан, курс байгаа | 200 | ERROR_INACTIVE_STUDENT |
| TC04 | Идэвхтэй оюутан, курс байхгүй | 200 | ERROR_NO_COURSE |
| TC05 | Идэвхтэй оюутан, суурь хичээл дутуу | 200 | ERROR_PREREQUISITES |
| TC06 | Оюутан болон курс хоёулаа байхгүй | 200 | ERROR_NO_STUDENT |
| TC07 | Идэвхгүй оюутан, курс байхгүй | 200 | ERROR_INACTIVE_STUDENT |
| TC08 | Идэвхтэй оюутан, суурь хичээл шаарддаггүй курс | 201 | OK |
| TC09 | Курс байгаа, studentID талбар дутуу | 400 | ERROR_BAD_REQUEST |

TC06, TC07-ийн алдааны эрэмбийг бодит ажиллуулалтаар тогтоосон. Амжилттай бүртгэлд registration.registrationID нь тоон төрөлтэй эсэхийг шалгасан бөгөөд яг утгыг шалгаагүй.

## 4. Ажиллуулах заавар (CMD)

Эхний CMD цонхонд `node server.js` ажиллуулна. Хоёр дахь CMD цонхонд:

```cmd
newman run lab05-collection.json > results\newman-pass.txt 2>&1
echo %ERRORLEVEL%
newman run lab05-collection-fail.json > results\newman-fail.txt 2>&1
echo %ERRORLEVEL%
```

Серверийг зогсоосны дараа:

```cmd
newman run lab05-collection.json > results\newman-down.txt 2>&1
echo %ERRORLEVEL%
```

## 5. Newman үр дүн

| Үзүүлэлт | PASS | FAIL | DOWN |
|---|---:|---:|---:|
| Requests | 21 | 21 | 21 |
| Failed requests | 0 | 0 | 21 |
| Assertions | 32 | 32 | 32 |
| Failed assertions | 0 | 1 | 32 |
| Passed assertions | 32 | 31 | 0 |
| Exit code | 0 | 1 (хүлээгдэж буй) | 1 (хүлээгдэж буй) |

FAIL болон DOWN-ийн exit code-ийг тусад нь баталгаажуулах шаардлагатай. DOWN-ийн тоог алдааны жагсаалтаас тооцсон: 21 холболтын алдаа, 32 assertion алдаа.

- [PASS тайлан](results/newman-pass.txt): 32/32 assertion амжилттай, нийт 1832 ms.
- [FAIL тайлан](results/newman-fail.txt): TC01-ийн oracle-д 201-ийн оронд 200 хүлээхээр зориудаар өөрчилсөн, 1 assertion алдаа.
- [DOWN тайлан](results/newman-down.txt): ECONNREFUSED, серверээс HTTP/JSON хариу ирээгүй.

FAIL нь oracle-ийн хүлээгдэж буй утга зөрсөн алдаа бол DOWN нь интерфейсийн холболтын алдаа бөгөөд хариу байхгүйгээс нэмэлт assertion алдаа үүссэн.

## 6. Дүгнэлт

Тестийн дизайны таван алхмаар бүртгэлийн функцийг сонгож, сонголт, төлөөлөх утга, спецификаци болон бодит тестүүдийг боловсруулсан. Хамгийн их бодол шаардсан алхам нь сонголтуудын хослолоос хэрэгжих боломжтой спецификаци гаргах байлаа. Оюутан байхгүй үед тухайн оюутны идэвхтэй төлөвийг шалгах боломжгүй, мөн курс байхгүй үед түүний суурь хичээлийг шалгах боломжгүй. Давхар алдаатай нөхцөлд оюутан байхгүй эсвэл идэвхгүй гэсэн алдаа курс байхгүйгээс түрүүлж буцаж байгааг тогтоосон. Есөн тестийн нөхцөлд 21 хүсэлт, 32 assertion ажиллуулж үндсэн collection дээр бүгд амжилттай болсон. Зааврын жишээтэй харьцуулахад PUT хариуны message, registrationID-ийн nested бүтэц болон prerequisite алдаанд missing массив байхгүй зэрэг ялгаа кодод ажиглагдсан. Мөн GET /courses/:id маршрут кодод хэрэгжээгүй боловч энэ маршрутыг тусад нь ажиллуулж тестлээгүй. FAIL туршилт нь буруу oracle-ийг Newman илрүүлж байгааг харуулсан. DOWN туршилт нь сервер унтарсан үед холболтын алдааг илрүүлсэн бөгөөд эдгээр зориудын алдааг серверийн бизнес логикийн согог гэж үзээгүй.
