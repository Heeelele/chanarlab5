# \## 4. Тестийн спецификаци

# 

# | ID | Тестийн нөхцөл | HTTP | Хүлээгдэж буй үр дүн |

# |---|---|---|---|

# | TC01 | Амжилттай бүртгэл | 201 | OK |

# | TC02 | Оюутан байхгүй | 200 | ERROR\_NO\_STUDENT |

# | TC03 | Идэвхгүй оюутан | 200 | ERROR\_INACTIVE\_STUDENT |

# | TC04 | Хичээл байхгүй | 200 | ERROR\_NO\_COURSE |

# | TC05 | Суурь хичээл дутуу | 200 | ERROR\_PREREQUISITES |

# | TC06 | Оюутан болон хичээл байхгүй | 200 | ERROR\_NO\_STUDENT |

# | TC07 | Идэвхгүй оюутан ба хичээл байхгүй | 200 | ERROR\_INACTIVE\_STUDENT |

# | TC08 | Суурь хичээл шаарддаггүй | 201 | OK |

# | TC09 | studentID талбар дутуу | 400 | ERROR\_BAD\_REQUEST |

# \## 9. Дүгнэлт

# 

# Энэхүү лабораторийн ажлаар Postman болон Newman ашиглан API системийн автомат тестийг хэрэгжүүлсэн. Тестийн дизайны таван алхмын дагуу тестлэх функц, сонголт, төлөөлөх утга, спецификаци болон бодит тестүүдийг боловсруулсан. Хамгийн их бодол шаардсан алхам нь сонголтуудын хослолоос хэрэгжих боломжтой тестийн спецификаци боловсруулах байсан. Оюутан байхгүй үед идэвхтэй төлөвийг, хичээл байхгүй үед суурь хичээлийн шаардлагыг шалгах боломжгүй болохыг тодорхойлсон. Давхар алдаатай нөхцөлд оюутны алдаа хичээлийн алдаанаас түрүүлж буцаж байгааг тогтоосон. Үндсэн collection-ийн 9 тестийн нөхцөл, 21 HTTP хүсэлт, 32 assertion бүгд амжилттай ажилласан. Заавар болон серверийн кодыг харьцуулахад PUT хариуны бүтэц, registrationID-ийн байрлал, missing массив болон GET /courses/:id маршруттай холбоотой ялгаа ажиглагдсан бөгөөд уг GET маршрутыг тусад нь тестлээгүй. FAIL туршилтаар Newman буруу test oracle-ийг амжилттай илрүүлсэн. DOWN туршилтаар сервер унтарсан үеийн холболтын алдааг илрүүлж, автомат тестийн хэрэгслийн ач холбогдлыг судалсан.
